你发的三份代码实际上实现了同一个目标：

输入自然语言问题 → 找到正确的 Excel 工作表 → 查询电影数据 → 返回答案。

但它们采用了三种不同的技术架构。

为了便于比较，我把它们命名为：

| 方案  | 框架         | 核心技术                                         |
| --- | ---------- | -------------------------------------------- |
| 方案一 | LlamaIndex | `RecursiveRetriever + PandasQueryEngine`     |
| 方案二 | LlamaIndex | `双 VectorStoreIndex + MetadataFilters`       |
| 方案三 | LangChain  | `FAISS + RunnableLambda + PythonAstREPLTool` |

这三种方案的根本区别不在于使用哪个向量数据库，而在于检索到工作表之后，如何获取具体答案。

- 方案一：递归跳转到 Pandas 查询引擎，由 Pandas 计算答案。
- 方案二：继续检索表格文本，由 LLM 阅读文本并判断答案。
- 方案三：手动路由到 LangChain 查询链，由 LLM 生成 Pandas 表达式，再通过 Python 工具执行。

# 一、三种方案的完整工作流程

## 方案一：LlamaIndex 原生递归检索

IndexNode + RecursiveRetriever

① 读取 Excel

按工作表创建多个 DataFrame

② 创建 IndexNode

年份摘要 + index_id

③ 创建 PandasQueryEngine

每个工作表对应一个引擎

④ VectorStoreIndex

仅索引工作表摘要

⑤ 用户提问 → 向量检索

命中年份_1994 的 IndexNode

⑥ RecursiveRetriever 自动跳转

index_id → PandasQueryEngine_1994

⑦ LLM 生成表达式 → Pandas 执行

计算评分人数最小值及对应电影

⑧ LLM 综合查询结果 → 最终回答

### 关键代码

建立映射：

```
node = IndexNode(    text=summary,    index_id=sheet_name)df_query_engines[sheet_name] = query_engine
```

假设 `sheet_name="年份_1994"`，就建立了：

```
IndexNode.index_id = "年份_1994"
            ↓
df_query_engines["年份_1994"]
            ↓
对应1994年DataFrame的PandasQueryEngine
```

执行递归检索：

```
recursive_retriever = RecursiveRetriever(    "vector",    retriever_dict={"vector": vector_retriever},    query_engine_dict=df_query_engines,)
```

当检索到 `IndexNode` 时，`RecursiveRetriever` 可以根据 `index_id` 找到并调用对应的下游查询引擎。这是 LlamaIndex 提供的原生递归检索机制。

[image](https://www.google.com/s2/favicons?domain=https://developers.llamaindex.ai\&sz=32)

LlamaIndex+1



最后生成答案：

```
retrieved_nodes = recursive_retriever.retrieve(query)response = query_engine.synthesize(    query,    nodes=retrieved_nodes)
```

你的代码把检索和答案生成显式拆成两步，还增加了对 Pandas 执行错误的检查。

方案一的特点：只建立一个摘要向量索引，实际电影数据保存在 DataFrame 中，由 Pandas 完成计算。

## 方案二：LlamaIndex 双向量索引检索

摘要路由 + 元数据过滤

① 读取 Excel 并清洗数据

评分人数转换为整数

② 摘要 Document

年份说明

sheet_name 元数据

③ 内容 Document

df.to_string()

sheet_name 元数据

④ summary_index

⑤ content_index

⑥ 第一次向量检索

从摘要索引中选出年份_1994

⑦ 第二次向量检索

先按 sheet_name 过滤，再在匹配内容中检索

⑧ LLM 阅读检索到的表格文本

直接比较文本中的评分人数

⑨ 生成自然语言答案

### 关键代码

建立两套文档：

```
summary_doc = Document(    text=summary_text,    metadata={"sheet_name": sheet_name})content_doc = Document(    text=df.to_string(index=False),    metadata={"sheet_name": sheet_name})
```

随后创建：

```
summary_index = VectorStoreIndex(summary_docs)content_index = VectorStoreIndex(content_docs)
```

第一次检索：

```
retrieved_nodes = summary_retriever.retrieve(query_str)matched_sheet_name = (    retrieved_nodes[0].node.metadata["sheet_name"])
```

第二次检索：

```
content_retriever = VectorIndexRetriever(    index=content_index,    similarity_top_k=1,    filters=MetadataFilters(        filters=[            ExactMatchFilter(                key="sheet_name",                value=matched_sheet_name            )        ]    ))
```

最后：

```
response = query_engine.query(query_str)
```

这里与方案一最大的不同是：没有 Pandas 查询引擎参与最终计算。

虽然加载 Excel 时使用了 Pandas，但是到了问答阶段，Pandas 已经不负责计算，LLM 直接根据检索到的文本回答。

还有一个你需要特别注意的细节：

```
content_doc = Document(text=df.to_string(index=False))content_index = VectorStoreIndex(content_docs)
```

这并不保证「一个工作表只对应一个向量节点」。

LlamaIndex 在构建索引时默认会根据分块设置把长 `Document` 切成多个节点，默认分割器通常是 `SentenceSplitter`，默认 `chunk_size=1024` Token。

[image](https://www.google.com/s2/favicons?domain=https://developers.llamaindex.ai\&sz=32)

Developer Documentation+1



因此，大工作表可能被分成多个节点，而你的：

```
similarity_top_k=1
```

只取其中最相似的一个节点。

这意味着 LLM 可能只看到1994年工作表的一小部分，而不是全部电影数据，从而无法正确确定全表的评分人数最小值。

## 方案三：LangChain 手动递归路由

FAISS + RunnableLambda + PythonAstREPLTool

① 读取 Excel

每个工作表转换为 DataFrame

② 摘要 Document

metadata.index_id

③ Pandas 查询链

Prompt + LLM + Python工具

④ FAISS.from_documents()

只为摘要建立向量索引

⑤ 向量检索命中摘要

读取 metadata["index_id"]

⑥ RunnableLambda 手动路由

根据 index_id 选择 Pandas 查询链

⑦ LLM 生成 Pandas 表达式

StrOutputParser 提取代码文本

⑧ ast.parse 检查语法 → PythonAstREPLTool 执行

得到电影名称和评分人数

⑨ 第二次 LLM 调用

将 Pandas 输出整理成自然语言

⑩ 最终回答

### 关键代码

第三种方案没有使用 LlamaIndex 的 `IndexNode`，而是使用普通的 LangChain `Document`：

```
node = Document(    page_content=summary,    metadata={"index_id": sheet_name})
```

创建 FAISS：

```
vector_index = FAISS.from_documents(    all_nodes,    embeddings)
```

手动路由：

```
def retrieve_table(query):    node = vector_retriever.invoke(query)[0]    index_id = node.metadata["index_id"]    result = df_query_engines[index_id].invoke(        {"query": query}    )    return {"query": query, "context": result}
```

每张表对应的查询链是：

```
query_engine = (    pandas_prompt    | llm    | StrOutputParser()    | RunnableLambda(        partial(            execute_pandas,            python_tool=python_tool        )    ))
```

最后：

```
query_engine = (    recursive_retriever    | response_prompt    | llm    | StrOutputParser())
```

这里的 `recursive_retriever` 实际上是你自己命名的 `RunnableLambda`，并不是 LlamaIndex 的原生递归检索器。

方案三的特点：整体思路与方案一接近，但用 LangChain 的 LCEL 管道和 Python 工具手动实现检索路由与计算。

# 二、三种方案的横向对比

# 三、同一个问题在三种方案中如何处理？

以你运行过的问题为例：

> 1994 年评分人数最少的电影是哪一部？

方案一

LlamaIndex 自动路由 + Pandas

问题 → 摘要检索 → IndexNode → RecursiveRetriever → PandasQueryEngine → 执行 `idxmin()` → LLM 总结

方案二

LlamaIndex 两次向量检索 + LLM 阅读

问题 → 摘要检索 → 获取 sheet_name → 内容过滤与检索 → LLM 阅读匹配的表格文本 → LLM 判断最小值

方案三

LangChain 手动路由 + Python 工具

问题 → FAISS 摘要检索 → 获取 index_id → RunnableLambda → LLM 生成表达式 → PythonAstREPLTool 执行 → LLM 总结

方案一和方案三最终可能执行相同的 Pandas 表达式：

```
df.loc[    df["评分人数"].idxmin(),    ["电影名称", "评分人数"]]
```

这两种方案都能在完整 DataFrame 上完成运算，不必把所有电影记录放进 LLM 的上下文。

而方案二需要让 LLM 直接分析检索到的文本，不能保证完成全表的精确比较。

# 四、三种方案分别有什么优缺点？

方案一：适合学习真正的递归检索

优点是 `RecursiveRetriever` 能自动沿着 `IndexNode` 的关联关系调用下游查询引擎，层次明确，也容易扩展到其他工具。

缺点是依赖 LlamaIndex experimental 模块，而且 `PandasQueryEngine` 执行模型生成的代码，需要考虑安全隔离。

[image](https://www.google.com/s2/favicons?domain=https://developers.llamaindex.ai\&sz=32)

Developer Documentation



方案二：适合学习两阶段 RAG 与元数据过滤

优点是流程比较直接，不需要动态执行 Python 代码，适合电影介绍、导演、演员等文本类问题。

缺点是需要构建两套索引。对于全表最值、求和、平均值等任务，容易因为检索不完整或模型数值推理错误而产生错误。

方案三：适合学习 LangChain 的 LCEL 链式编排

优点是每个阶段都可以独立修改：Prompt、LLM、代码执行器、检索逻辑、结果格式化器等都很明确。

缺点是你需要自己实现路由和异常处理，而且 `PythonAstREPLTool` 同样存在代码执行风险，`ast.parse(mode="eval")` 只是语法限制，并不提供安全沙箱。

## 五、还有三个需要重点改进的地方

第一，三份代码都可能路由到错误的年份。

它们都先对摘要进行向量相似性检索：

```
similarity_top_k=1
```

但年份属于精确匹配信息。如果问题明确写了 `1994年`，最好先通过规则提取年份并精确选择工作表，再利用向量检索处理模糊问题。

第二，方案一和方案三的数值计算准确性依赖于数据类型和生成的表达式。

你第三份代码成功运行后得到：

```
电影名称    燃情岁月
评分人数    176801
```

但最后 LLM 却回答「查询失败」，说明实际计算成功并不等于整个问答链一定正确。

另外，必须确认 `评分人数` 是数值类型，避免字符串形式的数字被按字典序比较。

第三，方案一和方案三都需要隔离动态代码执行。

LlamaIndex 官方对 PandasQueryEngine 提出了任意代码执行风险警告；LangChain 的 Python REPL 类工具也有相同类型的安全注意事项。仅靠提示词禁止 `import`、赋值或限制为表达式，不足以保证安全。

# 六、最终应该选择哪一个？

| 你的目标                             | 更合适的选择             |
| -------------------------------- | ------------------ |
| 学习 LlamaIndex 递归检索原理             | 方案一                |
| 学习 RAG 双索引、元数据过滤                 | 方案二                |
| 学习 LangChain、LCEL、RunnableLambda | 方案三                |
| 对 Excel 做精确数值统计                  | 方案一或三的计算思路         |
| 在不可信输入下部署生产系统                    | 三者均需进一步安全设计        |
| 处理大型 Excel 的最值、均值、排序             | 固定或受控的 Pandas 查询逻辑 |

如果你以后要将它们用于一个真正的 Excel 问答系统，我更倾向于组合三者的优点：

用户自然语言问题

年份提取 / 向量路由选择工作表

识别查询意图、列名与计算操作

受控 Pandas 函数执行

只允许预先定义的最值、均值、筛选等操作

返回结构化结果并生成答案

这样既保留向量检索的灵活性，也利用 Pandas 做精确计算，并避免直接执行任意模型生成的 Python 代码。

最后用三句话记住三份代码的差别：

方案一： LlamaIndex 自动找到表格查询引擎，让 Pandas 算。

方案二： LlamaIndex 找到表格内容，让 LLM 自己看、自己判断。

方案三： LangChain 手动找到表格查询链，让 LLM 写 Pandas 表达式，再交给 Python 工具算。

其中方案一是严格意义上使用了 `RecursiveRetriever` 的递归检索；方案二和方案三是手动编排的路由式检索流程。
